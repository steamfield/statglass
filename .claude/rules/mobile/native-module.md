# Native Module Rules

`apps/mobile/modules/statglass-native/` is a local Expo module in Swift. It vendors the
`StatglassCore.xcframework` built from `crates/statglass-mobile` and the Swift bindings
UniFFI generates for it (RFC `plan/rfc-ios-app.md` 4.3). The change path from Rust to a
screen is the `mobile-bridge` skill.

## The module is a pipe

- Commands are `call(method, argsJson) -> resultJson` in the desktop's `{ status, data | error }` shape, so `MobileTransport` maps one result type for both apps.
- Streams arrive as Expo module events tagged with a subscription id; Swift forwards the JSON it gets and never reorders, drops or coalesces messages, because `reduceLive` depends on the producer's ordering.
- Swift never parses, converts or formats metric data; meaning belongs to Rust and presentation to `@statglass/core`.
- Swift reports its own failures as typed module errors `{ kind: "keychain" | "secureEnclave" | "camera", osStatus, message }`, so `MobileTransport` can map them to a `NativeError` instead of a string.
- Add a method to the facade and the generated bindings, never a one-off Swift helper that computes something.

## Lifecycle

- `start()`, `quiesce()`, `quiesced()`, `resume()` and `pathChanged(path)` never block the calling thread. `quiesce()` issues every park request before it returns, so call it on the same serial queue as `resume()` to keep UIKit's order; async `quiesced()` resolves after Rust commits in-flight mirror writes.
- Background entry calls `beginBackgroundTask`, then `quiesce()`, awaits `quiesced()` off the queue, and ends the task when it resolves or expires; a foreground `resume()` never waits for `quiesced()`. Never join a Rust thread on the main thread.
- A callback whose JS listener is gone ends its subscription and is logged once, not per message.

## Signer

- Signing goes through one Swift protocol with two implementations: a Secure Enclave P-256 key on device and a Keychain `ThisDeviceOnly` software P-256 key in the simulator, which has no Secure Enclave.
- Choose the implementation at build time (`targetEnvironment(simulator)`), never from a runtime setting, so a device build can't fall back to a software key.
- Keys use `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`; they never sync, export or restore onto another device.
- Biometrics gate the app lock, never each signature, or every reconnect would prompt.
- Return the DER signature to Rust unchanged; Rust converts it to SSH's `(r, s)` form and has the test for it.

## Generated code

- The Swift bindings and the XCFramework are generated by `scripts/mobile/build-rust-ios.sh` and git-ignored; regenerate them, never edit them.
- After changing an exported Rust function or record, rebuild the XCFramework before running the app, or Swift calls a stale symbol and crashes at load.
- The simulator build and native module tests run locally through `make mobile-native-check` (prebuild, then `xcodebuild` build and test for the simulator; phase 4 adds it), and until it exists through `bun run --cwd apps/mobile expo run:ios`; no hosted macOS job runs them (D-118, D-131).
- `make mobile-check` is JS-only (Biome, tsc, jest, expo export, expo install --check, single-React) and never proves Swift compiled.
